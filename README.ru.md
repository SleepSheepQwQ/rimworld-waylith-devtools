# Pinpoint — точные нажатия для инструментов разработчика RimWorld 1.7 (Waylith, Android)

[English](README.md) · [简体中文](README.zh-CN.md) · **Русский**

Слой касаний порта отвечает на вопрос «по какому **объекту** пришлось нажатие», а отладочные
инструменты спрашивают «в какой **клетке** находится мышь». Pinpoint возвращает потерянную половину:
клетка под пальцем и есть ответ, а «прилипание» к объекту — исключение, которое нужно запросить,
оно ограничено и объяснимо.

> Раньше назывался `AgentDevTools`. Поведение то же, название честнее.

## Какие два дефекта устраняются

**1. Инструмент вообще не срабатывает.** Нажатие на карте превращается слоем касаний в
синтетический вызов выделения (`PortUI.MobileSelectionController.Tap`) и никогда не создаёт
`MouseDown`, который ожидает `LudeonTK.DebugTool.DebugToolOnGUI`. В результате активный инструмент
ничего не делает, а нажатие забирает выделение. Pinpoint фиксирует `UI.MouseCell()` и
`UI.MouseMapPosition()` на точке нажатия на время действия клика — и инструмент получает нужный ввод.

**2. Срабатывает не по тому объекту.** Прилипание к ближайшей цели правильно для игры и неправильно
для инструментов: очистка рельефа или спавн рядом с лежащим предметом «уезжали» на этот предмет.
Теперь кандидат принимается только если нажатие попало в собственную клетку объекта либо не дальше
16 dp от проекции его `DrawPos` — и никогда больше половины клетки на экране, поэтому отдаление
камеры не расширяет прилипание на соседние клетки.

## Режимы

Читается один раз при запуске из `files/game/pinpoint.mode`:

| Режим | Поведение |
|---|---|
| `off` | патчей нет, порт работает как есть |
| `auto` (по умолчанию) | прилипание только если нажатие действительно по объекту |
| `always` | прежнее поведение: всегда первая цель, которую сообщает порт |

Каждое решение пишется в лог вместе с причиной, поэтому ошибочный клик можно объяснить постфактум.

## Установка

Положить `Pinpoint` в `Mods/`, включить, перезапустить. Архив мода плоский — `About/` и
`Assemblies/` лежат в корне, именно этого ждёт встроенный установщик порта.

## Требования

RimWorld 1.7 (движок Waylith), Android-порт `com.ports1de.waylith`. Файлы игры не изменяются,
всё применяется во время выполнения через Harmony.
